### DNS MANAGER
---
Реализовал задание с использованием кластеризации, кластеры подтягивают информацию из работающих пиров, из неработающего или чужого бекапа информация о DNS серверах не получается.
 При включении пира будет подтягивать информацию из второго. Если изменять информацию в пире не через доступные консольные команды в приложении, а в ручную, об этом будет сообщаться в логах сервера. Информацию полученная извне не передастся другому пиру.\
 В данный момент все взаимодействия происходят с не настоящим etc/resolv.conf для избежания изменений на своём устройстве, для работы на сервере нужно изменить пути в конфигах

## Основные произведенные ручные тесты для проверки работоспособности
Перед всеми тестами были добавлены DNS-сервера, через команду add
1. Удаление файла resolv.conf, при перезапуске сервера файл восстанавливается из backup файла.
2. Удаление папки пира целеком, при перезапуске при наличии работающего второго пира первый восстанавливается.
3. Ручное изменение одного из resolv.conf, во второй пир или в backup информация информация не уходит.
4. Проверка на максимум серверов в файле, максимум равен 3, так как если добавить больше будут работать только они, остальные в теории могут быть записаны, но не работоспособны.
5. Запуск при невалидном бекапе и отстуствии resolv.conf, выдаст ошибку, при добавлении нового сервера будет перезписан бекап на валидный.

Здесь я перечислил основные тесты, но их было произведенно больше для провекри работоспособности


## Запуск программы

Создание бинарника CLI, эта часть реализованна с использованием Cobra поэтому требует дополнительных действий

```bash
go build -o dns-cli cmd/cli/main.go
```

или при наличии установленного make 

```bash
make build
```

Есть несколько вариантов использовании программы.
1. Без кластеризации.

```bash
go run ./cmd/server/main.go --config config/config.yaml
```

или 

```bash
make server
```

2. С кластеризацией.
Запуска узла А.

```bash
go run ./cmd/server/main.go --config config/node-a.yaml
```

или 

```bash
make server-a
```
Запуск узла Б.
```bash
go run ./cmd/server/main.go --config config/node-b.yaml
```

или 

```bash
make server-b
```

### Доступные команды
В следующих командах флаг addr обязателен только в кластерном режиме, когда один сервер можно без него.
Стандартные адреса при локальном разворачивании, указанные в конфиге.
Peer A - localhost:50051 
Peer B - localhost:50052

Добавление сервера по ip
```bash
./dns-cli --addr <address> add <ip>
```
Удаление сервера по ip
```bash
./dns-cli --addr <address> remove <ip>
```
Список серверов
```bash
./dns-cli --addr <address> list
```
